# 全站语言与主题检查

检查日期：2026-10-10。范围：全部九个页面，排除 visa.html。本轮仅检查，未修改应用代码。

## 结论

语言、主题控制器和设置保存基本正常，但页面内容翻译和主题样式覆盖不完整。多数页面的语言切换只影响导航；主题按钮切换成功后，主体样式仍保持原来的固定配色。

## 优先修复的问题

### 1. 主题属性变化，但主体样式未接通

六个带切换按钮的页面均能正确更新根节点主题属性和按钮提示。但比较浅色、深色下主内容区域的文字颜色、背景颜色、背景图和边框颜色，未发现有效变化。博客加载中的评论 iframe 类名变化属于加载状态，不是主题效果。

原因是大量页面样式写死颜色和渐变，覆盖了公共主题变量。例如 style.css 的个人页背景（2650 行）、博客背景（3745 行）、作品背景（5351 行）和状态面板背景（93 行）。应把页面背景、文字、面板、按钮、弹窗统一接入主题变量，并对浅色、深色分别定义。

截图：[博客浅色](blog-light.png)、[博客深色](blog-dark.png)、[个人页浅色](home-light.png)、[个人页深色](home-dark.png)。博客深色截图的月亮按钮已选中，但主体仍保持亮色。

### 2. 页面翻译覆盖不完整

projects.html、games.html、nav.html、dashboard.html 调用 setupSiteControls() 时没有页面词典，主体也缺少翻译标记。个人页和博客有页面词典，但只覆盖部分节点。个人页计时单位在 home.html 的动态生成逻辑中固定为“天、时、分、秒”；状态面板动态提示也需要随语言重新生成。

index.html、terminal.html、ssh.html 未调用语言应用逻辑，因此不能沿用其他页面选择的语言。全站浏览器标题也未随语言更新。site.js:148 固定设置 html.lang 为 zh-CN；当前大部分正文确实还是中文，完整翻译后应同步根语言，并对保留原语言的内容单独标注。

### 3. 博客评论区不跟随设置

blog.html:193–194 把 giscus 的 data-theme 固定为 noborder_light、data-lang 固定为 zh-CN。实际 iframe 在英文、深色模式下仍使用中文与浅色主题，日语下评论操作按钮也仍为中文。

应在初始化及语言、主题变化时同步评论组件配置。可保留二维码本身的白底以便识别，但弹窗外壳和文字也需要主题适配。

截图：[日语、深色模式下的社交弹窗](mobile-ja-modal.png)。

### 4. 辅助功能标签漏译

site.js:163 的 data-i18n-aria 处理只查公共词典，没有查询页面词典。博客 sortLabel 定义在页面词典中，英文下排序区域的 aria-label 实际变成多个按钮文字的拼接，而不是预期的“Sort content”。一些搜索、社交、弹窗关闭标签也仍是中文。

### 5. 多标签页与自动主题联动不完整

一个标签页修改语言、主题后，另一个已经打开的页面仍保留旧设置，刷新才更新；没有监听 storage 变化。正常跨页跳转和刷新保存是有效的。

“自动”模式按系统 prefers-color-scheme 选择主题，并不是根据当前时间切换。带 setupSiteControls 的页面注册了系统偏好变化监听；首页、终端、SSH 仅在加载时解析主题，没有相同的实时监听。此次没有修改真实操作系统主题，后者依据代码检查。

## 已通过的检查

- 六个带控制器的页面测试了简体中文、繁体中文、英文、日语；选择状态和菜单收起正常。
- 六个页面主题按钮循环与属性更新正常；语言、主题可跨页保存，刷新后保留。
- 390 × 844 模拟窄屏下，博客语言菜单和社交弹窗可操作，未出现页面横向溢出。
- 检查后恢复简体中文和自动主题。

## 其他观察与限制

桌面博客的固定侧栏高度超过视口时，底部 GitHub 入口曾落在可点击区域之外；窄屏重新排版后可操作。建议同时检查侧栏最大高度与滚动方式。

此次使用本地浏览器、桌面及模拟窄屏检查，并读取页面 DOM 与计算样式。没有检查签证页，没有进行真实手机或真实系统主题变化测试，也未把终端固定深色直接判定为缺陷。截图、DOM 和 measurements.json / secondary-measurements.json 保存在本目录。

建议修复顺序：页面主题变量 → 页面界面词典与动态文案 → 评论组件同步 → 标题与辅助功能标签 → 多标签页同步。
